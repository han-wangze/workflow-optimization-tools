# 手游市场研究 · 数据分析脚本

游戏行业战略分析实习期间（2025.11–2026.02）把几类固定流程脚本化。扫榜、抓自媒体、清洗问卷都属于**流程固定但手工做又慢又易错**的工作，多轮之间的口径还要求完全一致——交给脚本更稳。

| 脚本 | 解决什么 | 输入 → 输出 |
|---|---|---|
| `new_release_scanner.py` | Sensor Tower 免费榜的新品扫描 | 榜单导出 csv × N → 本周新增新品清单 + 更新后的去重表 |
| `bilibili_crawler.py` | 跟踪游戏 UP 主的新游相关投稿 | UP 主 UID 列表 → 投稿标题 / 链接 / 时间 csv |
| `concept_test_stats.py` | 多轮概念测试问卷的批量清洗与统计 | 问卷 Excel × N → 各品类指标表 + 批量汇总表 |

---

## 1. new_release_scanner.py — 新品扫描

**为什么需要**：每周要从 Sensor Tower 的 App Store 免费榜（top free）里筛出当年新上线的新品。人工比对历史名单重复且易错，而且榜单导出格式有两种，列名不一样。

**怎么做**

- **格式自适应**：榜单有两种导出格式（`Downloads` / `Revenue ($)` 一族，与 `iPhone downloads` / `iPhone revenue ($)` 一族），自动识别并映射成统一字段。
- **筛选口径**：榜单为免费榜、上线年份为目标年、且「排名变化含 new 或 排名 + 排名变化 > 100」——最后一条用来捞到当期明显往上冲的产品。
- **去重与回写**：读入累积的已扫描产品去重表（仅 `app name` 一列），剔掉已收录过的，剩下的就是本周新增；再把新增产品追加回去重表，并做一次空记录清理。
- **职责拆分**：识别格式、筛选、去重、回写各自独立成方法，改一处不影响其他处。

**运行**

```bash
# 先建好目录并放入数据
mkdir -p data/export
#   data/export/          ← 放 Sensor Tower 导出的榜单 csv（tab 分隔、utf-16）
#   data/scanned_apps.xlsx ← 已扫描产品去重表，需含 app name 列
python new_release_scanner.py
```

输出：`data/export/ST_new_games_<时间戳>.xlsx`（本周新增）与 `data/export/scanned_apps_updated.xlsx`（更新后的去重表）。

> 注：筛选年份在 `apply_filters()` 里写死为目标年份，换年份后需要改这一行。

## 2. bilibili_crawler.py — B 站内容抓取

**为什么需要**：新品扫描不只看榜单，还要看 B 站游戏 UP 主最近发了哪些新游。人工翻投稿效率很低。

**怎么做**

- 用 `bilibili-api-python` 官方库**异步**抓取标题 / 链接 / 发布时间。
- **日期先解析再比较**：`parse_date()` 把 `YYYY-MM-DD` 字符串转成 `datetime` 后再和投稿时间比，避免字符串直接比较出错。
- **倒序提前退出**：投稿按发布时间倒序返回，一旦翻到早于起始时间的投稿就立刻停，不做无谓翻页；不足一页也直接结束。

**运行**

```bash
# 先改脚本顶部的 UP_UIDS / START_DATE / END_DATE
pip install bilibili-api-python aiohttp
python bilibili_crawler.py
```

输出：脚本所在目录下的 `bilibili_videos.csv`（UTF-8-BOM，Excel 直接可读）。

> 抓公开投稿不需要登录；`CREDENTIAL` 默认三项留空，只有需要访问受限内容时才把浏览器 Cookie 填进去——**不要把它提交进版本库**。

## 3. concept_test_stats.py — 概念测试问卷批处理

**为什么需要**：概念测试每轮会回收一批问卷 Excel，每轮都要清洗、并按同一套口径算下载意愿 / 尖叫度 / 游玩时长。手工做慢，而且跨轮口径很难保持一致。

**怎么做**

- **列名自适应**：问卷题号与措辞每轮都会变，用「固定题号前缀 + 关键词」和正则自动识别「游玩时长列」「已填写字段」「品类问题列」，换一轮问卷通常不用改代码。
- **口径严格固定**（这是这个脚本真正要解决的问题）：
  - **样本量** = 「有出于爱好体验过」的用户 ∪ 「整体愿意但未选具体试玩意愿」的用户，按序号去重；
  - **整体下载意愿** = 「愿意试玩」人数 ÷ 样本量；
  - **尖叫度** 只在「愿意试玩」这个子集内取均值（排除未作答的 `-`）；
  - **游玩时长占比** 的分母是**「已填写」字段为正向值的样本数**，而不是总样本数——否则未填答的人会被错算成「不打算长玩」；
  - 男 / 女性指标用各自的子样本量分别做分母；
  - 愿意 / 不愿意下载的原因占比分别以「愿意试玩」和「不愿意试玩」人数为分母。
- **异常不中断**：单个文件或单个品类统计失败时记下失败原因继续跑，最后输出成功 / 失败计数，批量跑不会因为一份坏表全盘丢失。

**运行**

```bash
#   data/questionnaires/  ← 放待处理的问卷 Excel（每份一个文件）
python concept_test_stats.py
```

输出到 `output/`：每份问卷一份 `<文件名>_统计结果.xlsx`（含「统计结果」与「原始数据」两个页签），外加一份合并所有轮次的 `批量处理汇总表.xlsx`。

> 换一版问卷时，如果游玩时长列的题号前缀或题材关键词变了，改脚本顶部 `DURATION_COL_PREFIX` / `DURATION_COL_THEME_KEYWORDS` 两个常量即可。

## 关于示例值

仓库代码中的路径、UP 主 UID 与题材 / 品类名（`概念A`、`示例品类A` 等）都是脱敏后的占位示例值，替换成实际值即可运行，业务逻辑与统计口径完整保留。代码不含任何公司内部数据、产品指标或未公开结论。
